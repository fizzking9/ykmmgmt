# 模拟业务数据 — 零售销售运营（Retail Sales）

一套带外键关系的模拟业务数据，用于完整演练：建表（Schema Manager）→ 导入 → 数据浏览 → 视图 → 可视化 → 仪表盘。

## 数据模型（5 张表，外键链）

```
departments 部门
   └──< employees 员工 (员工.部门编号 → 部门.部门编号)
products 商品
orders 订单 (订单.销售员工编号 → 员工.员工编号)
   └──< order_items 订单明细 (明细.订单编号 → 订单.订单编号，明细.商品编号 → 商品.商品编号)
```

| 文件 | 建议英文表名 | 中文显示名 | 行数 |
|---|---|---|---|
| 01_部门.csv | departments | 部门 | 4 |
| 02_员工.csv | employees | 员工 | 12 |
| 03_商品.csv | products | 商品 | 15 |
| 04_订单.csv | orders | 订单 | 80 |
| 05_订单明细.csv | order_items | 订单明细 | 160 |

## 建表步骤（按此顺序，外键目标必须先存在）

在 数据表管理 → 新建数据表（手动创建）中依次创建。编号列均勾选“主键”。

1. **departments（部门）**
   - dept_id 整数，主键，标签：部门编号
   - dept_name 字符串(50)，标签：部门名称
2. **employees（员工）**
   - emp_id 整数，主键，标签：员工编号
   - emp_name 字符串(50)，标签：姓名
   - dept_id 整数，外键 `departments.dept_id`，标签：部门编号
   - position 字符串(50)，标签：职位
   - hire_date 日期，标签：入职日期
3. **products（商品）**
   - product_id 整数，主键，标签：商品编号
   - product_name 字符串(100)，标签：商品名称
   - category 字符串(50)，标签：类别
   - unit_price 小数，标签：单价
4. **orders（订单）**
   - order_id 整数，主键，标签：订单编号
   - customer_name 字符串(100)，标签：客户名称
   - region 字符串(20)，标签：区域
   - emp_id 整数，外键 `employees.emp_id`，标签：销售员工编号
   - order_date 日期，标签：下单日期
   - amount 小数，标签：订单金额
5. **order_items（订单明细）**
   - item_id 整数，主键，标签：明细编号
   - order_id 整数，外键 `orders.order_id`，标签：订单编号
   - product_id 整数，外键 `products.product_id`，标签：商品编号
   - quantity 整数，标签：数量
   - subtotal 小数，标签：小计金额

## 导入顺序（外键约束要求）

上传页面按此顺序导入对应 CSV（文件表头即中文标签，自动匹配）：

01_部门 → 02_员工 → 03_商品 → 04_订单 → 05_订单明细

## 数据特征

- 订单时间分布：2026-01-01 ~ 2026-08-19（适合时间序列：月/周粒度）
- 区域：华东 / 华北 / 华南 / 西南
- 商品类别：智能硬件 / 配件 / 耗材 / 服务
- 订单仅由销售部员工（101、102、103、104、112）产生
- 订单金额 = 该订单明细小计之和（数据自洽）

## 可回答的业务问题（演练建议）

- 每月销售额趋势？（订单.下单日期 时间序列 + 订单金额 SUM）
- 哪个区域贡献最大？（区域 分组 + 订单金额 SUM）
- 哪些商品类别卖得最好？（订单明细 JOIN 商品，按类别聚合 小计金额）
- 销售员的业绩排名？（订单 JOIN 员工，按姓名聚合）
- 各部门人员规模？（员工 JOIN 部门，COUNT）
- 客单价分布？（订单金额 直方图）

## 外键冲突演练（可选）

故意把某行 CSV 的 部门编号 改成不存在的值（如 99）再导入，该行应计入“拒绝”，且不影响其他行。

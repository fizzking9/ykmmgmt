# Changelog

All notable changes to YKMMgmt are documented in this file.

---

## 2026-08-31

- **Login and user accounts (multi-user support):** The system now requires every user to sign in — opening any page without being logged in shows a Chinese login screen instead of the data, and a first 超级管理员 (super administrator) account is created during setup from private configuration. Three account levels control who can do what: 超级管理员 has full control — it creates and manages all other accounts, can never be locked out or demoted through the app, and is created only during setup; 管理员 (administrator) has all data rights — uploading files, managing table structures, creating and deleting views, charts, and dashboards — but can only manage ordinary user accounts, never other administrators; and 用户 (regular user) can browse data, views, charts, and dashboards but cannot change anything. The menus adapt to each account: admin-only items like 数据导入, 数据表管理, and the builders are hidden from regular users, as are all edit and delete buttons on the management lists — and these restrictions are enforced by the system itself, not just hidden in the interface. Sessions stay signed in for two hours and renew themselves silently for up to a week, so users are rarely interrupted; when a session truly ends, the app returns to the login screen and then back to whatever page the user was on. A new 用户管理 page (visible to administrators only) lets accounts be created with a role, passwords reset, roles changed, and accounts temporarily disabled — a disabled user can no longer sign in until re-enabled. All 10 validation gates passed, with 194 backend and 90 frontend tests green.

- **Data import hub:** The upload page is now a single 数据导入 hub with a method switcher across the top — 上传文件 (upload files), 数据抓取 (data scraping, shown as a coming-soon placeholder for a future phase), and 导入历史 (import history). The import history, previously its own page in the sidebar, now lives as a tab inside the hub, keeping all ways of getting data into the system in one place. A realistic sample retail dataset (five linked tables: 部门, 员工, 商品, 订单, 订单明细 with proper foreign-key relationships) was added to the project folder for practicing the full workflow — creating tables, importing data, browsing it, and building views, charts, and dashboards.

## 2026-08-28

- **PNG export for visualizations and dashboards:** Charts and dashboards can now be saved as picture files directly from their management lists. On the 可视化 (visualizations) and 数据看板 (dashboards) list pages, every row has a new 导出 button that downloads that single item as a PNG image — a visualization exports with its name as a title at full size, and a dashboard exports its whole layout with every chart, KPI card, and text tile as it appears on screen. A new 批量导出 button beside 新建 switches the list into a selection mode with checkboxes, plus 全选 / 清空 / 导出所选 / 取消 controls, so many items can be exported in one go; batch exports save straight to the browser's usual download folder without any save dialog, and each file name starts with a timestamp (e.g. dashboards_2026-08-28_10-30-05) so a batch stays grouped and sorted together. All 71 frontend tests pass, and repeated exports — including exporting the same item twice in a row, which previously could get stuck showing 正在导出 forever — were verified to complete in about a second each in the browser.

## 2026-08-20

- **Data browsing & analysis refinements:** A round of usability fixes and improvements across the data browser, view builder, charts, and dashboards. In the Data Browser, filter conditions now offer the full set of comparison options already known from the View Builder — text columns support 等于/不等于/包含/开头是/结尾是/为空/不为空, numeric columns support 大于/小于 and their inclusive variants, and date columns get a simple start/end date range instead of an operator — so browsing data can be narrowed precisely without building a view first. In the View Builder, a column used for grouping can now be renamed directly through the column list (a small 已分组 badge marks it), and it appears exactly once in the results instead of being duplicated; removing a joined table now automatically cleans up every column, filter, grouping, aggregation, sort, and computed column that referenced it, so previews and saves can no longer fail on leftover references. For charts and dashboards, two related problems were fixed: a chart that gained a time configuration after being placed on a dashboard previously stayed stuck on a loading spinner, and time-series charts reacted inconsistently to the dashboard's global time-granularity switch (changing to 周 looked odd, switching to 日 seemed to have no effect). Time-series charts now take their time settings automatically from their X axis — the separate 时间配置 section collapses to a “同X轴” note — and the dashboard's date range and granularity controls apply cleanly and consistently to them (日/周/月/季/年 each render correctly), while other chart types keep their manual time configuration. 148 backend and 65 frontend tests pass, with full in-browser verification of every fix.

## 2026-08-19

- **Phase 11 — Legacy Business Table Removal & System Reset:** YKMMgmt is now a fully generic data platform. The three original built-in business tables (退费单, 服务退款工单, 钱包提现操作) and every hardcoded table-specific cleansing rule have been removed: a single reversible Alembic migration drops the tables and hard-deletes everything that referenced them — saved views, visualizations, and dashboards built on them, their import history (data sources and import jobs), and orphaned column/table metadata. A fresh installation now starts with zero business tables — the Schema Manager shows an empty list on first launch — and every table is created by users through the Schema Manager, with uploads flowing through the general cleaning pipeline exactly as before. The view-only protection for preset tables and the read-only badges are gone along with them, and the table-specific rule registry now ships empty but remains fully functional for future code-level rules. The test suite was rebuilt around the new reality: all view, visualization, dashboard, data-browser, and import tests create their tables dynamically through the real Schema Manager and import APIs, and a new regression test guards against any built-in business tables ever returning. Along the way, a latent view-builder bug was fixed where table names ending in digits (e.g. sales_2026) were mistaken for self-join aliases and truncated. All 8 validation gates passed — including a complete in-browser walkthrough on a fresh database covering table creation, CSV upload, data browsing, views, charts, and dashboards — with 139 backend and 65 frontend tests passing.

## 2026-08-14

- **Phase 10 — Database Schema Management:** The database structure can now be managed entirely inside the app — no hand-written models, SQL, or migration files. A new Schema Manager section lists every table with its Chinese name, column count, and row count; each table's detail page shows every column's type, constraints, Chinese label, description, and default value alongside a sample of its data. New tables can be created from scratch (column-by-column with a backend-driven type picker) or from a CSV file whose structure is automatically inferred and offered for review first, and they appear immediately in the Data Browser and View Builder with no server restart. Columns can be added, removed, retyped, renamed, and annotated with Chinese labels, descriptions, and default values, and foreign keys can point at another table's primary key or unique column through a guided two-level picker. Tables and columns can be renamed — the system blocks a rename that would break saved views or visualizations — and deletion requires explicit confirmation with a full dependency warning; the three original business tables are protected as view-only. Every change automatically writes and applies a real Alembic migration. Beyond the original scope, data uploads into dynamic tables were hardened end-to-end: file columns match tables by their Chinese labels (with multiply-BOM-prefixed files cleaned up automatically), files whose columns do not belong to the target table are rejected wholesale with a clear list of missing and unexpected columns, and each table can be configured with an upsert key (single or composite, defaulting to the primary key) and an exact-duplicate deduplication toggle. Import results now report exact 新增/更新/跳过/拒绝 counts — re-uploading an unchanged file counts everything as skipped, changed values as updated, and rows violating constraints as rejected only, never double-counted. Edit-page tooltips warn that renaming a table can detach its data-cleansing rules and that Chinese labels drive upload column matching. 147 backend and 63 frontend tests pass, including a full-lifecycle integration test covering create → upload → data views & charts → schema edit → re-upload → delete.

## 2026-08-11

- **Phase 9 Dashboard Refinements:** Following hands-on use, the dashboard experience received a broad polish. The sidebar section is now named 数据看板 with a 看板列表 entry and a new 看板创建 shortcut, and the dashboard list no longer shows the tile-count column. On the dashboard page, tiles are visually quieter — the title bar is gone, and hovering a tile reveals a compact toolbar with its name, refresh, and full-screen actions — while the header gained one-click refresh of the whole dashboard, PNG export, PDF export, and a shareable link. The time controls were reworked into a single tidy row: quick ranges (最近7天/最近30天/本月/最近3个月/今年) fill the date pickers beside them and un-highlight as soon as dates are edited manually; regrouping is now a tab strip — 默认 / 日 / 周 / 月 / 季 / 年 — with week and quarter bucketing newly supported end-to-end, and a small info icon explains which tiles respond to the filter. In the builder, the canvas now shows the real charts and KPI values exactly as they will appear (no more placeholder tiles), tiles can be configured, previewed, or removed from a hover toolbar, a 配置 action jumps into the chart builder with a one-click way back, and an expanded full-canvas popup allows comfortable what-you-see-is-what-you-get rearranging. KPI cards and charts now scale to fill their tiles completely — values size themselves to the tile — so nothing scrolls and exports capture every chart whole, and chart tooltips respect the configured number format instead of showing floating-point noise. 107 backend and 51 frontend tests pass.

- **Phase 9 — Dashboard Builder & Management:** The system now delivers the single, live dashboard the team checks every day: saved charts can be composed onto a free-form canvas where every tile can be dragged into place and resized, then saved under a unique name. Three kinds of tiles are supported — any saved chart from the visualizations library, free-form text or markdown notes for titles and explanations (with a live preview while editing), and brand-new KPI number cards created on the spot by choosing a data view, a column, a label, and how values are combined (sum, average, count, minimum, or maximum), with no need to save a chart first. Dashboards appear automatically in the sidebar under a new collapsible 仪表盘 section for one-click access, and a dedicated management page lists every dashboard with its description, tile count, and sortable creation/last-updated times, plus view, edit, rename, and delete actions — renaming and deleting always ask for confirmation, and duplicate names are handled with the same conflict flow used for views and charts. The dashboard view page shows every tile with live data, a per-tile refresh button (nothing refreshes automatically, keeping the system quiet), and a full-screen mode for presenting a single chart. Most importantly, a global time control bar lets viewers filter the whole dashboard by date range, regroup by year, month, or day, and choose the aggregation — and it automatically applies only to charts that declare a time column in the new optional 时间配置 section of the chart builder; charts without one keep working unchanged and show a subtle hint that they do not respond to the time filter. On small screens the dashboard switches to a clean read-only stacked layout, and editing is reserved for desktop viewports with a clear message. Every new screen, button, hint, and error message is in Chinese. All 13 Phase 9 validation gates passed, including full in-browser verification, with 106 backend and 48 frontend tests.

## 2026-08-10

- **Phase 8 — Saved Visualizations Management:** Saved charts are now first-class items that can be browsed, opened, updated, and cleaned up from a dedicated Visualizations page, reachable from a new sidebar entry. The list shows every saved chart with a miniature preview that is an exact scaled-down copy of the real chart (tables and KPI cards show a type icon instead), plus its name, type, source view, and creation and last-updated times; clicking a preview opens the chart full-size. Chart previews load once and stay cached while moving between pages, so returning to the list never re-runs every query — data refreshes only when the user presses the refresh button, keeping the system quiet and the experience fast. Editing a chart opens the familiar builder with every setting restored, and deleting always asks for confirmation first. Chart names are now unique: saving with a name that already exists asks whether to update that existing chart, and the change appears everywhere immediately without needing to refresh. Both the Visualizations and Data Views lists gained a last-updated column and sortable time columns (click to sort oldest-first, newest-first, or back to default), plus a create-new button that jumps straight into the respective builder. Pie charts also received three upgrades: clicking a legend entry hides or restores that slice with the remaining percentages recalculated automatically, very small slices no longer clutter the chart with stacked labels (their values move to the legend), and users can choose how each slice's value is combined — sum, average, count, minimum, or maximum. All 11 Phase 8 validation gates passed, with 85 backend and 32 frontend tests.

- **Phase 7 — Visualization Builder:** Saved data views can now be turned into shareable charts through a new visual builder, reachable either from the "可视化" button on any saved view or from its own page. Users pick one of eight chart types — table, KPI card, bar chart, line chart, pie chart, scatter plot, histogram, and boxplot — and see a live preview that always uses the complete dataset behind the view, not a sample. Every chart can be customized with a title, axis labels, one of four color themes, and number formatting (decimal places, thousands separators, and a currency prefix). Bar charts are now restricted to categorical columns and let users choose how values are combined per category (sum, average, count, minimum, or maximum), so totals per status or per service type are one click away. Line and scatter charts can split data by a category: each class gets its own color and point shape, the legend mirrors those shapes exactly, and hovering over any point reveals its values and its category. Time-based charts offer day/month/year grouping and a drag handle to zoom into a date range. Two new distribution charts support deeper analysis: histograms overlay multiple numeric variables in semi-transparent layers (with adjustable bin count) so their shapes can be compared directly, and boxplots summarize each category with its median, quartiles, and outliers. Finished charts can be exported as PNG images, copied as a shareable link, and saved for later editing — reopening a saved chart restores every setting. All 15 validation gates passed with 84 backend and 24 frontend tests.

## 2026-08-06

- **Phase 6 — Saved Data Views Management:** Views created in the builder can now be saved, listed, previewed, edited, and deleted through a complete management interface. A new Data Views page displays all saved views in a table with their names, descriptions, and creation dates. Each view row has four action buttons: a preview dialog that executes the view's saved SQL and shows paginated results (up to 100 rows per page), an edit button that opens the view builder pre-filled with the view's full configuration including tables, joins, columns, filters, groupings, and computed columns, and a delete button with a confirmation dialog that permanently removes the view. Views with duplicate names are prevented through a confirmation flow — if a user saves with an existing name, they are asked whether to update the existing view or choose a different name. Preview column headers now display Chinese table and column labels by default, matching the format shown throughout the rest of the application. Three new API endpoints round out the backend: GET /api/views lists all saved views with metadata, GET /api/views/{id}/data executes stored SQL with pagination, and DELETE /api/views/{id} permanently removes a view. All 14 Phase 6 validation gates passed: zero linting warnings across backend and frontend, zero TypeScript errors, 49 backend tests and 10 frontend tests passing.

## 2026-08-05

- **Phase 5 — Data View Builder:** Users can now create custom data views by combining tables, picking columns, defining filters, and applying groupings with aggregation — all through a visual builder without writing SQL. A new View Builder page provides a split-panel interface where every configuration choice is immediately previewable. The system supports multi-table joins (INNER, LEFT, RIGHT) with visual join key configuration, self-joins with automatic alias disambiguation for comparing records within the same table, and type-aware filter operators that adapt to whether a column contains numbers, dates, or text. Computed columns allow chained arithmetic operations (addition, subtraction, multiplication, division) between numeric columns with automatic null handling via COALESCE, plus date offset calculations (adding or subtracting days, months, or years). Each computed column can be optionally included in the SELECT output, used in filters, added to GROUP BY, or referenced in aggregations. Behind the scenes, the system generates clean parameterized SQL with no value interpolation, stores both the visual configuration and the compiled SQL for full transparency, and validates all table and column references at save time. When editing an existing view, all configuration is pre-populated and the SQL regenerates only when the underlying configuration changes. State persists across navigation so work is never lost. All 22 validation gates passed: Ruff and ESLint zero warnings, TypeScript zero errors, 41 backend tests and 10 frontend tests passing, and the complete create-preview-update lifecycle verified end-to-end.

## 2026-07-30

- **Phase 4 — Application Interface & Data Upload:** A full web application interface replaces the previous single-page health display. The app now features a responsive sidebar navigation that adapts to desktop and mobile screens, with organized groups for Data Management (数据管理) and Data Visualization (数据可视化). The centerpiece is a complete data upload page where users can drag and drop CSV or Excel files, select a target data table from a dropdown, and upload with a single click. During upload, the interface shows progress and prevents accidental double-submissions. After import completes, a detailed result card appears showing how many rows were created, updated, skipped, or had errors — with a direct link to view the full import history. The import history page displays all past uploads in a paginated table with color-coded status badges (green for success, red for failure, yellow for in-progress) and columns for file name, target table, row counts, and timestamps. Behind the scenes, three critical reliability fixes were applied: import jobs are now visible in history immediately (no longer hidden until completion), the upload state persists even when navigating between pages, and a numeric comparison bug that falsely reported 2,085 rows as "updated" on identical re-uploads has been resolved. All 16 validation gates passed, including 28 backend tests and 10 frontend tests with zero formatting or linting issues.
- **Phase 3.5 — Smart Data Refresh (Upsert):** Re-uploading a data file now intelligently updates existing records instead of creating duplicates or silently discarding them. For Refund Orders (退费单) and Service Refund Work Orders (服务退款工单), the system matches records by their business ID numbers — if a record already exists, its data is refreshed with the latest values and the import timestamp is updated. For Wallet Withdrawals (钱包提现操作), which lack a natural business ID, the system computes a digital fingerprint of all column values and skips identical rows to prevent duplication. Import job reports now provide a detailed breakdown: how many rows were newly created, how many were updated, and how many were skipped as duplicates — while keeping the total count backward-compatible. Added 6 integration tests covering all three business tables, plus an Excel file import test. All 14 validation gates passed. Updated project documentation with upsert behavior reference and import API examples.

## 2026-07-29

- **Phase 3 — Data Import Engine:** A single file upload interface now accepts both CSV and Excel files. Chinese column headers in uploaded files are automatically matched to the correct database fields — no manual column renaming needed. Every file goes through a six-step data cleaning process before entering the database: whitespace trimming, empty row and column removal, duplicate row elimination, date and number format standardization, value validation, and table-specific structural fixes. Each import produces a detailed cleaning report showing exactly what was modified, removed, or flagged. If a file has mismatched or missing columns, the system rejects it immediately with a clear explanation of what's wrong. All three sample datasets were successfully imported — totaling approximately 60,000 rows across Refund Orders (退费单), Service Refund Work Orders (服务退款工单), and Wallet Withdrawals (钱包提现操作). 19 automated tests verify the cleaning pipeline, file parsers, and validation logic. All code quality checks passed.
